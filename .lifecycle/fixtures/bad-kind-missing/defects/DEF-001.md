# DEF-001

Feature: FEAT-2026-001
Summary: concurrent driver and rear-occupant writes to the same zone could both
apply, leaving the stored value and the applied zone gain briefly divergent.

## Reproduction
Deterministic. Harness issues `setZoneOffset(zone=rear, +3dB, role=normal)` and
`setZoneOffset(zone=rear, -2dB, role=driver)` within 4 ms. Reproduced 47 times
in 500 interleavings before the fix.

## Escape point — where was it INTRODUCED?
`implementation` (F12). The per-zone command queue was created correctly per
DES-1, but the queue handler took the arbitration decision before enqueueing
rather than after, so two writes admitted in the same tick each believed they
had won.

Requirement AC-001-9 was correct. The F8 concurrency model was correct and
named a deterministic winner. The F9 state machine was correct. This was a
coding error against a correct design.

## Detection point — where was it CAUGHT?
`integration` (F14, IT-4). Not caught at unit level because UT-6 as originally
written exercised the arbitration function in isolation rather than through the
queue.

## Root cause
Why it was possible: the design specified *that* arbitration precedes storage
but the unit test asserted arbitration in isolation, so the ordering between
arbitration and enqueue was never asserted anywhere at unit level.

## Classification

process_originated: false

Justification per §12.2: no lifecycle artifact was inadequate. The requirement,
architecture, concurrency model and detailed design all specified the correct
behaviour and a deterministic winner. The gap was a coding error plus a unit
test that tested the right function at the wrong seam. Neither is a defect in a
checklist, template or gate — a G3 checklist item asking "is the winner
deterministic" was present and passed correctly, because the design *was*
deterministic.

## Symptom correction (§12.3 — always required)
`src/audio/zone_offset_owner.cpp`: arbitration moved inside the queue handler,
after dequeue, so exactly one command per zone can be in the arbitrating state.

## Escape correction (§12.3 — applies only when process_originated)
**None required.** This is the case v1.0 would have forced a checklist change
for, producing checklist inflation without preventive value.

## Missing artifact added
UT-6 rewritten to drive the queue rather than the arbitration function
directly, so the ordering invariant is asserted at unit level — the level that
should have caught it.
