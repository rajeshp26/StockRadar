# Checklist — G3.5 Design Traceability

Gate: `G3.5` · Layer: lifecycle (new) · Certifier: **Reviewer**
Governed by: spec §9.2, §8.4, §8.6.
`CONDITIONAL`: permitted with a specific, owned, dated condition. Forbidden anywhere in an L4 feature.

## 0. Pre-checklist blocking checks

- [ ] Author and certifier identity blocks complete; identity rule satisfied (§9.1.1).
- [ ] Design baseline id assigned for this certification (§8.6 rule 1).

## 1. Chain complete in both directions

- [ ] `UC → CMP` complete: every use case allocated to at least one component.
- [ ] `CMP → IFC/EVT` complete: every inter-component interaction has a contract.
- [ ] `IFC/EVT → DES` complete.
- [ ] `DES → IMP` complete: every design element has at least one implementation unit.
- [ ] `AC → DES` complete: every acceptance criterion mapped to at least one design element.
- [ ] `NFR → DES` complete.
- [ ] Every edge navigable in reverse, so the three §8.2 questions can be answered mechanically.

## 2. Orphan check — all ten classes (§8.4)

Run `.lifecycle/scripts/orphan-check.py`. Every class must be zero. Record counts in the ledger rather than asserting the result.

- [ ] orphan requirement — `AC-*`/`NFR-*` with no design element and no test case: **0**
- [ ] orphan scenario — `SCN-*` with no `AC-*` and no recorded deferral: **0**
- [ ] orphan test — test covering no `AC-*`, `NFR-*` or contract: **0**
- [ ] orphan component — `CMP-*` allocated to no `UC-*`: **0**
- [ ] orphan contract — `IFC-*`/`EVT-*` with no consumer or no owner: **0**
- [ ] orphan code — changed file with no `IMP-*` and no `AC-*`: **0**
- [ ] orphan impact — F10 impacted path with no selected regression test: **0**
- [ ] orphan state — mutable state with no owner, or more than one owner: **0**
- [ ] orphan risk — `SCN-*` with no risk score, or `high`/`critical` with no F15 case: **0**
- [ ] stale baseline — `AC-*`/`NFR-*` whose baseline is `superseded` with gates unreopened: **0**

## 3. Baseline currency (§8.6)

- [ ] Every `AC-*`, `NFR-*`, `IFC-*`, `EVT-*` and `DES-*` records the baseline it belongs to.
- [ ] No element in scope belongs to a `superseded` baseline, or the `changes` entry shows the change does not touch this gate's scope.
- [ ] The `changes` entry for any supersession records element, before text, after text, reason, impact set, and gates reopened.

## 4. Audio Settings instantiation

- [ ] Every settings use case allocated across the layers it actually crosses: HMI, Audio Service, HAL, VACS, persistence, backend sync.
- [ ] Each control scope's persistence path traced to a design element, not left implicit.
- [ ] Focus and ducking design elements traced to the arbitration component, not to the HMI.
- [ ] Audible-outcome acceptance criteria traced to a design element that reaches the audio path, not only to a state write.
- [ ] Backend sync conflict resolution traced to a named design element.
