# Checklist — G7 Lifecycle Requirements Verification

Gate: `G7` · Layer: lifecycle (new) · Certifier: **Verifier**
Governed by: spec §9.2, §8.4, §8.5, §8.6, §9.1.2, §12.4.
`CONDITIONAL`: **forbidden** at this gate (§9.2). Forbidden anywhere in an L4 feature.

> Naming (§9.2): this is the **Lifecycle Requirements Verification Gate**. It is not Automotive SPICE SWE.6 itself. §14 maps them; the mapping is not a compliance claim.

## 0. Pre-checklist blocking checks

- [ ] Author and certifier identity blocks complete (§9.1.1).
- [ ] The certifier is not the author of the requirements, design or code under test, by `agent_id` **and** `session_id`.
- [ ] At L4: `certifier.role != author.role`, and certifier contributed nothing in any prior session.
- [ ] Certified against the **current** baseline; zero `stale baseline` orphans (§8.6 rule 5).

## 1. Requirements coverage

- [ ] Every `AC-*` has at least one executed test with a recorded result.
- [ ] Every `NFR-*` measured by its stated method, with the **measured value** recorded, not a pass assertion.
- [ ] Zero `orphan requirement` under §8.4.
- [ ] Zero `orphan test` under §8.4.

## 2. Risk-earned depth (§5.2.2) — v1.1

- [ ] Every applicable `SCN-*` tested at the depth its risk band earns.
- [ ] Every `high` scenario has an executed F15 case, or a deferral with recorded Reviewer concurrence.
- [ ] Every `critical` scenario has an executed F15 case. No deferral is permitted.
- [ ] Zero `orphan risk` under §8.4.

## 3. Impacted paths

- [ ] Every F10 impacted path has an **executed** regression test with a result.
- [ ] Zero `orphan impact` under §8.4.

## 4. Coverage thresholds (§8.5)

- [ ] Every metric in the selected set from `F5-test-analysis.md` measured, with the measured value recorded.
- [ ] Every threshold met, or the gate FAILS.
- [ ] At L3+, `risk_coverage` present in the selected set and measured as the fraction of `high` and `critical` scenarios with a case at the required depth.
- [ ] No claim of "100% test coverage" appears anywhere in the evidence (§8.5).

## 5. Immutable evidence (§9.1.2)

- [ ] Every evidence item records `claim`, `command`, `commit`, `environment`, `timestamp`, `result_file`, `checksum`.
- [ ] Result files committed under `features/<ID>/evidence/F1{4,5}-*/`.
- [ ] An assertion with no result file FAILS.

## 6. Test integrity

- [ ] No test relaxed, retuned or weakened to accommodate observed behaviour.
- [ ] Failures investigated to a cause, not re-run until green.
- [ ] Flaky tests, if any, enumerated with an owner; a flaky test is not evidence.

## 7. Regression verification — RED→GREEN with controlled exception (§12.4)

For every regression test added for a defect in this feature:

- [ ] **Preferred path:** test recorded failing before the fix and passing after, both with immutable references.
- [ ] **Exception path**, only when deterministic pre-fix reproduction is impossible, for one of: production-only environment, hardware-only failure, timing-dependent failure, nondeterministic race, external backend condition, unavailable old software build, safety validation environment.
  - [ ] The applicable condition is named and why it applies is documented.
  - [ ] At least **two** alternative-evidence items supplied from the §12.4 list. **Fewer than two FAILS.**
  - [ ] Reviewer approval recorded, with identity.
- [ ] No entry reads "could not reproduce" followed by a passing test with nothing further.
- [ ] Exception rate recorded as a test-fidelity indicator, not as a violation.

## 8. Audio Settings instantiation

- [ ] Every control scope verified end to end: vehicle, seat and `shared_vehicle`.
- [ ] Per-seat isolation verified at system level, not only at unit level.
- [ ] `shared_vehicle` simultaneous driver and co-pilot writes executed, with the deterministic winner observed matching the §6.6 model.
- [ ] Focus acquire, loss and regain executed; ducking onset, release and duck-during-user-change executed.
- [ ] Mute and unmute verified for audible outcome.
- [ ] Concurrent stream and multi-zone conditions executed at their risk-earned depth.
- [ ] Persistence verified across restart, reboot, upgrade, downgrade and rollback, on **read and write** paths.
- [ ] Backend sync verified for offline write, reconnect merge, and conflicting device-versus-backend modification.
- [ ] **Audible-outcome verification executed on `bench_hu` or `vehicle`**, recorded separately from state-readback results. A feature whose only evidence is state readback FAILS this item.
- [ ] Where alert, chime or warning audibility is in scope, §11 controls evidenced and no `CONDITIONAL` appears anywhere in the feature.
