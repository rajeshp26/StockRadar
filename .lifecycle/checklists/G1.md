# Checklist — G1 Contract Validation

Gate: `G1` · Layer: **existing** (§15.1) · Certifier: **Reviewer**
Governed by: spec §9.2, §6.4.1, §6.4.2.
`CONDITIONAL`: permitted with a specific, owned, dated condition. Forbidden anywhere in an L4 feature.

> §15.1: this gate keeps its existing implementation and enforcement machinery. The lifecycle **adds evidence** to it; the existing definition wins on any conflict. `config.yml` `external_gates.definitions_location` names the authoritative source.

## 0. Pre-checklist blocking checks

- [ ] Author and certifier identity blocks complete; identity rule satisfied (§9.1.1).
- [ ] Contract baseline id assigned for this certification (§8.6 rule 1).

## 1. Coverage of interactions

- [ ] Every inter-component interaction has a contract file in `F7-contracts/`.
- [ ] No interaction is implemented ahead of its contract file existing.
- [ ] Each contract states exactly one `owner` and an explicit `consumers` list.
- [ ] Each contract states a `version`.
- [ ] Each contract states `traces` to `UC-*` and `AC-*`.
- [ ] No consumer depends on a behaviour the contract does not declare.

## 2. Boundary declaration — v1.1

- [ ] Every contract declares `boundary`: `in_process`, `ipc` or `network`.
- [ ] Boundary matches `config.yml` `layers.*.process_boundary` and `boundary_kind` for the seam it crosses.

## 3. Reliability semantics are declared, not universal (§6.4.1)

For each of `timeout`, `retry`, `idempotency`, and error contract:

- [ ] `applicable: true` with the concrete semantic stated, **or** `applicable: false` with a `reason`.
- [ ] No field silently omitted. Omission FAILS; an explicit `false` with a reason PASSES.
- [ ] A contract with `boundary: ipc` or `network` marking `timeout.applicable: false` survived explicit Reviewer challenge, with the challenge recorded.
- [ ] `errors` enumerated for every operation that can fail.

## 4. Event semantics — complete or FAIL (§6.4.2)

For every `EVT-*`:

- [ ] `delivery` stated.
- [ ] `ordering` stated.
- [ ] `duplication.possible` stated.
- [ ] `consumer_idempotency.required` stated.
- [ ] `replay.supported` stated.
- [ ] `retention.duration` stated.
- [ ] `dead_letter.applicable` stated.
- [ ] `compatibility` stated.
- [ ] **Coupling rule:** `delivery: at_least_once` with `consumer_idempotency.required: false` FAILS as an incomplete contract.
- [ ] Publisher is exactly one component; subscribers enumerated.

## 5. Orphan contracts

- [ ] Zero `orphan contract` under §8.4 — no contract with no consumer, and none with no owner.

## 6. Audio Settings instantiation

- [ ] HMI → Audio Service contracts declare `boundary: ipc` with a real timeout.
- [ ] Audio Service → HAL and HAL → VACS contracts declare `boundary: ipc`, with timeout, retry and idempotency each explicitly decided.
- [ ] Backend sync contracts declare `boundary: network`, with retention and dead-letter decisions recorded.
- [ ] In-process validation-style interfaces may mark timeout and retry inapplicable, with a reason — but must still decide idempotency.
- [ ] Settings-change events state `ordering` at a scope that matches the control scope: per-vehicle, per-seat or per-user.
- [ ] Focus and ducking notifications state duplication and consumer idempotency, since arbitration re-notifies.
- [ ] Any contract carrying a per-user or account-scoped payload names its privacy classification.
