# Checklist — G5 Frontend Conformance

Gate: `G5` · Layer: **existing** (§15.1) · Certifier: **Reviewer**
Applies only when the feature has a UI surface (`config.yml` `depths.<L>.ui_gates_conditional`).
`CONDITIONAL`: permitted with a specific, owned, dated condition. Forbidden anywhere in an L4 feature.

> §15.1: existing gate. The lifecycle supplies UI acceptance criteria and the design-system conformance record. The existing definition governs enforcement.

## 0. Pre-checklist blocking checks

- [ ] Author and certifier identity blocks complete; identity rule satisfied (§9.1.1).
- [ ] `config.yml` `ui_surface.design_system_rules` and `ui_surface.accessibility_rules` are bound. **If unbound, this gate cannot be certified.**
- [ ] Applicability confirmed: the feature has a UI surface. If not, record `NOT_APPLICABLE` with a reason instead of PASS.

## 1. Design-system conformance

- [ ] Components drawn from the project design system rather than bespoke equivalents.
- [ ] Any bespoke component carries a recorded reuse search (§6.7) and a justification.
- [ ] Spacing, type, colour and state styling conform to the bound rules.
- [ ] Interaction states present: default, focus, pressed, disabled, loading, error.

## 2. Accessibility

- [ ] Conformance evaluated against the bound accessibility rules.
- [ ] Touch targets meet the stated minimum.
- [ ] Contrast meets the stated minimum.
- [ ] Every control has an accessible name.
- [ ] Screen-reader traversal order is sensible and recorded.
- [ ] Accessibility `NFR-*` from F3 are each addressed.

## 3. Localization

- [ ] No hard-coded user-facing strings.
- [ ] Layout tested at the longest supported language expansion.
- [ ] Locale-specific formats handled where the feature displays numbers, units or times.

## 4. Requirements linkage

- [ ] Every UI `AC-*` maps to a rendered element or behaviour.
- [ ] Every rendered element traces to an `AC-*`. Undeclared UI is scope with no requirement.

## 5. Audio Settings instantiation

- [ ] Control scope is visible to the user: a per-seat control is distinguishable from a per-vehicle one on the surface itself.
- [ ] `shared_vehicle` controls indicate when the driver has constrained or overridden the value.
- [ ] Disabled or unavailable settings state **why** they are unavailable rather than failing silently.
- [ ] Values reflect the authoritative owner's state, not an optimistic local echo, or the optimistic echo and its reconciliation are both specified.
- [ ] Role-dependent visibility matches `config.yml` `user_roles`: driver, co_pilot, normal, kids, guest.
- [ ] Driving-context restrictions applied where a control is restricted while driving.
