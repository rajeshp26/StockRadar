# Checklist — G0.5 Independent Test Challenge

Gate: `G0.5` · Layer: lifecycle (new) · Certifier: **Verifier**
Governed by: spec §9.2, §5.5, Rule D1 (§3.4). Ledger format: §9.1.
`CONDITIONAL`: **forbidden** at this gate (§9.2). Forbidden anywhere in an L4 feature.

## 0. Applicability — Rule D1

**G0.5 is mandatory whenever F5 is performed.** That includes L1. There is no depth at which F5 happens and this gate does not. `config.yml` `rules.g0_5_mandatory_when_f5_performed: true` is authoritative.

- [ ] F5 was performed at this depth, therefore this gate applies.
- [ ] `config.yml` `depths.<L>.gates` contains `G0.5` for the declared depth.

## 1. Pre-checklist blocking checks

- [ ] Author and certifier identity blocks complete (§9.1.1).
- [ ] `certifier.agent_id != author.agent_id` and `certifier.session_id != author.session_id`, where author is the F3 requirements author.
- [ ] At L4: `certifier.role != author.role`, and certifier contributed nothing to F3 in any prior session.
- [ ] F5 was re-derived against the **current** requirements baseline, not a superseded one (§8.6).

## 2. The F5 → F3 loop — four blocking steps (§5.5)

- [ ] **Step 1.** `TC-*` derived from requirements, the risk-ranked matrix, and independent analysis.
- [ ] **Step 2.** Every condition with no corresponding requirement was raised as a missing-scenario finding to F3.
- [ ] **Step 3.** F3 was amended and F5 re-derived against the amended baseline.
- [ ] **Step 4.** Zero missing-scenario findings remain open.

There is no `CONDITIONAL` path around step 4, at any depth.

## 3. Independence of the analysis — detectable signature

- [ ] At least one `TC-*` exists that no `AC-*` mentions. **Zero such conditions FAILS this gate** — that is the signature of transcription, which the Verifier charter prohibits.
- [ ] Count recorded in the ledger: `TC-* not derivable from any AC-*: N` where `N >= 1`.

## 4. Technique attribution (§5.2.1, §5.5)

Each technique either produced a recorded `TC-*` or is marked not applicable with a reason. At L1 the block is scoped "as applicable".

- [ ] equivalence partitioning
- [ ] boundary value analysis
- [ ] state-transition coverage
- [ ] decision tables
- [ ] error guessing
- [ ] interruption and resumption
- [ ] timeout and retry
- [ ] concurrency
- [ ] persistence across restart, reboot, upgrade, downgrade, rollback
- [ ] configuration and platform variants
- [ ] connectivity variants
- [ ] performance
- [ ] security
- [ ] usability
- [ ] accessibility
- [ ] observability
- [ ] Every `TC-*` records which technique produced it.

## 5. Risk-earned depth (§5.2.2)

- [ ] Every `SCN-*` risk-scored; zero `orphan risk` under §8.4.
- [ ] Every `high` scenario has a case at F15.
- [ ] Every `critical` scenario has a case at F15 and F16, with no deferral.
- [ ] Band assignments match `config.yml` `priority.bands` boundaries.

## 6. Test basis and traceability

- [ ] Requirements ↔ test conditions traceability is bidirectional and navigable both ways.
- [ ] Environment matrix states where each case runs, using `config.yml` `test_surfaces`.
- [ ] Selected coverage set recorded in `F5-test-analysis.md`, drawn from `coverage_menu`.
- [ ] At L3+, `risk_coverage` is in the selected set (§8.5).
- [ ] Thresholds stated numerically, not as adjectives.

## 7. Audio Settings instantiation

- [ ] Conditions exist for each audio-specific dimension: focus owner, ducking, mute, zones, concurrent streams, endpoint set, amp/DSP variant, seat occupancy.
- [ ] Focus-loss and focus-regain conditions present, not only focus-acquire.
- [ ] Ducking conditions cover duck onset, duck release, and duck during an active user change.
- [ ] Control-scope conditions cover per-seat isolation: a seat change must not alter another seat's value.
- [ ] `shared_vehicle` conditions cover simultaneous driver and co-pilot writes.
- [ ] Backend sync conditions cover offline write, reconnect merge, and conflicting device-versus-backend modification.
- [ ] Persistence conditions sweep read **and** write paths across restart, reboot, upgrade, downgrade and rollback.
- [ ] At least one condition asserts **audible outcome** on a surface with a real audio path — `bench_hu` or `vehicle` — distinct from any state-readback condition.
