# Definition of Done versus Verification

Definition of Done is a set of **claims** asserted by the Implementer:
requirements addressed, code implemented, tests added, contracts updated where touched,
review passed, applicable gates invoked.

Verification is **evidence** that each claim is true in this run: the test executed, the exit

## Ambiguity and Assumptions
Do not proceed when uncertain: state assumptions explicitly. Do NOT guess. Present multiple interpretations with tradeoffs when ambiguity exists (don't pick silently - give at least 2 options), stop and name what is unclear when confused and ask for clarification, and push back when warranted - if a simpler approach satisfies the requirements.

## Investigation and POC tasks

An investigation/POC task is complete when evidence was gathered, hypotheses were classified
and recorded in the claim ledger, verification ran under the canonical runtime, results were
compared against the recorded claim, the root cause was classified, and any remaining
uncertainty is recorded as a claim rather than omitted. An agent cannot convert an unverified
observation into a conclusion.
